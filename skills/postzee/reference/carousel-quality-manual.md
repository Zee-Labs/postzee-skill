# Carousel Quality Manual — The Editorial Journalism Standard

This manual defines the **content density and structure** of every carousel — block by block, slide by slide, with target word counts. It is the structural backbone that the editorial filter (`carousel-editorial-filter.md`) and design principles (`carousel-design-principles.md`) operate on top of.

A carousel that follows the format but lacks density reads thin. A carousel that has density but breaks the structure feels chaotic. This file ensures both.

---

## 1. The identity statement

> **You are a Brazilian editorial journalist with deadline pressure, not an AI translating American copy.**

Every block of text the agent writes must pass this test: would this paragraph survive an editor's red pen at a national publication? If not, rewrite.

The voice is:
- **Specific** — names, numbers, places, dates
- **Opinionated** — has a thesis, defends it
- **Economical** — every sentence earns its space
- **Allergic to ornament** — no decoration, no hype

The voice is **not**:
- Coach
- Influencer
- Tutorial-bot
- Marketing-hyped corporate

---

## 2. The 18-block / 9-slide structure

A standard 9-slide carousel contains exactly **18 text blocks**. Each block has a defined function and a target word count. This is the structural ideal — adapt for 5/7/12 slide variants per §6.

| Slide | Block | Target words | Function |
|---|---|---|---|
| **1** Capa | 1 — Headline | ~7 | The chosen headline (full, untruncated) |
| **2** Dark | 2 — Setup | ~14 | Locate the reader; give context |
| | 3 — Tension | ~18 | Name the friction the carousel exists to address |
| **3** Light | 4 — Data point | ~12 | First evidence, anchored to a source |
| | 5 — Reading | ~22 | The agent's interpretation of the data |
| **4** Dark | 6 — Friction | ~16 | The conflict / paradox / contradiction |
| | 7 — Reframe | ~20 | The thesis flips the reader's prior assumption |
| **5** Light | 8 — Big stat / Comparison | ~10 | Anchor number / before-after / table |
| | 9 — Implication | ~24 | What the stat means for the audience |
| **6** Dark | 10 — Case / Example | ~22 | A specific instance (named brand, person, situation) |
| | 11 — Mechanism | ~22 | How the thing actually works |
| **7** Light | 12 — Counterpoint | ~18 | Secondary tension; honest objection |
| | 13 — Resolution | ~24 | Synthesis — the carousel's defended position |
| **8** Gradient | 14 — Future direction | ~26 | What this points to next |
| | 15 — Trade-off | ~24 | The honest cost of the position |
| **9** CTA | 16 — Frase-ponte | ~18 | Mandatory bridge linking carousel to CTA |
| | 17 — CTA | ~14 | The action verb + handle |
| | 18 — Keyword box | ~6 | The single word/phrase user types to trigger |

**Total target word count for the carousel: ~310 words.**

That's tight. This is intentional — every slide must earn its space at 1080×1350. Long copy doesn't fit at 36-40px body type without crowding.

---

## 3. Word-count tolerance

| Range | Status |
|---|---|
| **80-120% of target** | ✅ Pass |
| **60-80% of target** | ⚠️ Thin — add density |
| **120-150% of target** | ⚠️ Crowded — trim |
| **< 60% of target** | ❌ Fail. Block too thin to carry meaning |
| **> 150% of target** | ❌ Fail. Won't fit at design type scale |

The editorial filter's "Densidade" parameter (one of the 7) maps directly to this table.

## 4. The 4 narrative arcs — block adaptation

Each carousel type bends the 18-block structure slightly. The blocks remain; their *content* shifts.

### 4.1 Tendência Interpretada (interpreted trend)

The 18 blocks above are the canonical Tendência Interpretada layout. Use as-is.

### 4.2 Tese Contraintuitiva (contrarian thesis)

| Slide | Block focus |
|---|---|
| 1 — Capa | Headline that contradicts consensus |
| 2 — Dark | Block 2: state the prevailing belief. Block 3: name what about it is wrong |
| 3 — Light | Block 4-5: evidence #1 against the consensus |
| 4 — Dark | Block 6: the friction → why people still believe it. Block 7: the actual reframe |
| 5 — Light | Block 8-9: evidence #2 (the strongest) |
| 6 — Dark | Block 10: a specific case that proves the thesis. Block 11: mechanism |
| 7 — Light | Block 12: when the consensus IS still right (intellectual honesty). Block 13: resolution — when to apply the new thesis |
| 8 — Gradient | Block 14: what to do differently starting now. Block 15: trade-off |
| 9 — CTA | Frase-ponte → CTA |

### 4.3 Case / Benchmark

| Slide | Block focus |
|---|---|
| 1 — Capa | Named brand/person + the contraintuitive result |
| 2 — Dark | Block 2: who they are. Block 3: what they did that was unusual |
| 3 — Light | Block 4: the *before* metrics. Block 5: how to read those metrics |
| 4 — Dark | Block 6: the move (the specific decision). Block 7: why it counterintuitive |
| 5 — Light | Block 8: the *after* metrics. Block 9: implication for similar businesses |
| 6 — Dark | Block 10: what they did week by week (concrete chronology). Block 11: the mechanism |
| 7 — Light | Block 12: what didn't work / what they almost gave up on. Block 13: lessons replicable |
| 8 — Gradient | Block 14: where to apply this in your own context. Block 15: where this case is NOT replicable |
| 9 — CTA | Frase-ponte → CTA |

### 4.4 Previsão / Futuro

| Slide | Block focus |
|---|---|
| 1 — Capa | Forward-looking projection (12-36 months) |
| 2 — Dark | Block 2-3: signal #1 already happening (with date) |
| 3 — Light | Block 4-5: data behind signal #1 |
| 4 — Dark | Block 6-7: signal #2 |
| 5 — Light | Block 8-9: signal #3 (the strongest) |
| 6 — Dark | Block 10: convergence — what signals 1+2+3 mean together. Block 11: mechanism of compounding |
| 7 — Light | Block 12: scenarios where this prediction fails. Block 13: probability-weighted resolution |
| 8 — Gradient | Block 14: action window — when to act. Block 15: cost of acting too early / too late |
| 9 — CTA | Frase-ponte → CTA |

## 5. The mandatory frase-ponte (block 16)

The CTA slide cannot land cold. The first block on slide 9 — **the frase-ponte** — bridges the carousel's content to the CTA.

**Function:** Reframe what the audience just learned into a reason to act.

**Structure:** One or two sentences, ~18 words total.

**Examples:**

For a carousel about creator economy → "A próxima virada do mercado vai ser invisível pra quem não está prestando atenção."

For a contrarian thesis on productivity → "Quem ainda mede produtividade em horas vai assistir o jogo terminar de fora."

For a case study on a brand → "A diferença entre quem replica e quem só admira é uma decisão por semana, e ela cabe num comentário."

**What it is NOT:**
- A summary of the carousel
- A "salva esse post" line
- A vague platitude ("E aí, o que você acha?")

If the agent skips the frase-ponte and jumps straight to "Comenta CARROSSEL pra receber o link" — the slide reads as a discontinuity. Always include block 16.

## 6. Slide-count adaptations (5 / 7 / 9 / 12 slides)

The 18-block structure is calibrated for 9 slides. When the user asks for a different size, follow these adaptations:

### 6.1 — 5 slides

| Slide | Function | Blocks merged from canonical |
|---|---|---|
| 1 Capa | Headline | 1 |
| 2 Dark | Setup + tension + first data | 2, 3, 4 |
| 3 Light | Reading + reframe | 5, 7 |
| 4 Dark | Big stat + implication + case | 8, 9, 10 |
| 5 CTA | Frase-ponte + CTA + keyword | 16, 17, 18 |

Lost: friction (6), mechanism (11), counterpoint (12), resolution (13), future (14), trade-off (15). For tight content this works; for nuanced positions it under-delivers — push back to 9 slides if possible.

### 6.2 — 7 slides

| Slide | Function | Blocks |
|---|---|---|
| 1 Capa | Headline | 1 |
| 2 Dark | Setup + tension | 2, 3 |
| 3 Light | Data + reading | 4, 5 |
| 4 Dark | Friction + reframe | 6, 7 |
| 5 Light | Big stat + implication | 8, 9 |
| 6 Dark/Light | Case + mechanism + resolution | 10, 11, 13 |
| 7 CTA | Frase-ponte + CTA + keyword | 16, 17, 18 |

Lost: counterpoint (12), future direction (14), trade-off (15).

### 6.3 — 9 slides (canonical)

The 18-block structure as-is.

### 6.4 — 12 slides

Add 3 slides between canonical 6 and 7:

| Extra slide | Function |
|---|---|
| 6.5 — Dark | Second case (block 10b) — different industry, same mechanism |
| 6.7 — Light | Quote / data card — anchor block (block 8b) — visual variety |
| 6.9 — Dark | Reader's question (block 12b) — anticipating the audience's "yeah but…" |

12-slide carousels work for tutorial-heavy / case-heavy content. Don't pad to fill — only use 12 if you genuinely have 12 blocks worth saying.

## 7. The 7-step revision process (run before approval)

Before offering the script for user approval, run these 7 steps:

### Step 1 — Block-count check
Count blocks. Match to the table in §2 (or §6 for non-9 slide carousels). Missing blocks → add. Extra blocks → cut or merge.

### Step 2 — Word-count check per block
For each block, measure word count. Apply tolerance from §3. Adjust.

### Step 3 — Density flow check
Read the carousel start-to-finish. Density should crescendo: setup → tension → max density at blocks 8-13 → cooldown → CTA. If a slide in the middle reads thinner than slide 2 — fix.

### Step 4 — Editorial filter pass
Run every block through `carousel-editorial-filter.md` §2 (banned constructions) and §4 (5-question test). Replace failures.

### Step 5 — 7-parameter scoring
Score each slide on the 7 parameters (`carousel-editorial-filter.md` §5). All ≥ 8/10 = pass. Any below 8 = revise that specific block.

### Step 6 — Frase-ponte presence check
Slide 9 (or last slide) MUST contain block 16 (the frase-ponte). Not optional.

### Step 7 — Aloud test
Read every slide aloud. Stumbles, awkward articles, register mismatches → fix.

Only after all 7 steps pass does the agent offer the script for user approval.

## 8. The 5 final tests — last gate before render

Even after revision, these 5 final tests catch what slipped through:

### Test 1 — Folha test
Could each slide appear in a column at Folha de São Paulo, NYT, or Piauí magazine? **No → rewrite.**

### Test 2 — Substitution test
Replace the topic word (e.g. "marketing" → "agronegócio"). Does the carousel still "kind of work"? **Yes → too generic, rewrite with specific anchors.**

### Test 3 — Promise test
Every promise made (slide 1 hook, mid-carousel claims) — is it anchored to a fact in the same or next slide? **No → add anchor or cut promise.**

### Test 4 — Article test
Read aloud. Any missing or extra Portuguese article? **Yes → fix.**

### Test 5 — Binary test
Does the carousel rely on a forced X-vs-Y dichotomy that doesn't exist in reality? **Yes → reframe.**

If any test fails, do **not** advance to render. Surface the failure to the user, explain in one sentence, propose the fix.

## 9. Penalty rules — the cap-the-score table

When scoring blocks (§5 step 5), these penalties cap the maximum achievable score:

| Issue detected | Max score for that block |
|---|---|
| Missing article | 7/10 |
| Two missing articles in same block | 5/10 |
| Banned construction (`carousel-editorial-filter.md` §2) | 5/10 |
| Pure-revelation framing ("o segredo de…") | 4/10 |
| Block under 60% of target word count | 6/10 |
| Block over 150% of target word count | 6/10 |
| Block fragmented into 3+ short sentences (picotado) | 5/10 |
| Two parallel sentences with same weight (no progression) | 6/10 |
| Coach / advisor register detected | 5/10 |
| Unsourced specific data claim | 6/10 |

A block hit by 2+ caps may end up < 8 even if the writing is otherwise fine — that's the system working. Rewrite from scratch instead of patching.

## 10. Title / heading hierarchy within slides

Each slide (except cover and CTA) typically has:

- **Tag / label** — 13px 700 letter-spacing 3px UPPERCASE — single short phrase identifying the slide's role ("DADO", "CASE", "IMPLICAÇÃO")
- **Heading** — 64-80px depending on dark/light — the slide's anchor sentence (block A from the table in §2)
- **Body** — 36-40px — the supporting block (block B from the table)

When a slide title reads "Segredo número 4" or "5 dicas" — it's failing. Replace with content-specific titles:

| ❌ Generic | ✅ Specific |
|---|---|
| "DICA Nº 3" | "200 CLUBES EM SP. 3 MODELOS DE NEGÓCIO." |
| "POR QUE ISSO IMPORTA" | "QUEM PERDE CRÉDITO NESSA EQUAÇÃO" |
| "ENTENDENDO O CENÁRIO" | "BANCOS BRASILEIROS DESDE 2022" |
| "A LIÇÃO" | "ONDE A REPLICAÇÃO QUEBRA" |

The internal heading is a mini-headline. Treat it with the same rigor as slide 1's hook — just shorter.

## 11. The fact-density floor

Every carousel must contain **at least 2 named-source facts** (data with attribution) and **at least 1 specific case** (a real brand, person, place, or event).

Without these, the carousel reads as opinion. With them, it reads as analysis.

The data anchors live in:
- Block 4 (data point)
- Block 8 (big stat)
- Block 10 (case)

If the user's brief lacks the raw data, the agent must either:
1. Ask for the data (one round of questions, not many)
2. Search the web (if WebSearch is available)
3. Note explicitly to the user: "Estou usando placeholder em [X]. Substitua antes de publicar."

Never fabricate statistics.

---

## 12. The "speaking out loud" test (read every slide aloud)

The single best filter for editorial quality is reading every slide aloud, with normal speed and natural pauses. The mouth detects what the eye misses.

Symptoms of failure (mouth catches them):
- Stumble on a missing article
- Tongue trips on awkward word order
- Sentence runs out of breath before the period
- Voice flattens on a sentence that lacks rhythm
- Cringe on a word the agent would never say at dinner

Fix the cause, not the symptom.

---

## 13. The output of this manual

When run end-to-end, this manual produces a carousel script that:

- Has **18 blocks** of correctly-sized text (or the appropriate count for the slide-count variant)
- Passes the **7-parameter scoring** at ≥ 8/10 each
- Survives the **5 final tests**
- Includes the **mandatory frase-ponte** before the CTA
- Anchors at least 2 facts to named sources
- Reads as written by an editorial journalist, not by an AI

That's the bar. Below the bar — do not advance to render.
